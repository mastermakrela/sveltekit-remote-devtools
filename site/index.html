sveltekit-remote-devtools
GitHub npm

Every remote function call, decoded.

A dev-only panel for SvelteKit remote functions. It lists every query, command and form in your app, shows each call with its real argument and result, and tells you which queries a write refreshed.

bun add -D sveltekit-remote-devtools

Timeline

Remote calls travel as base64url(devalue), so the Network tab is no help. The timeline decodes them: the argument, the result, the status and how long the server took.

  • Calls made while the page rendered on the server are grouped under that render.
  • For forms you see what the server received after validation, not just the raw body.
  • Each command and form shows its refresh tree: the queries the client asked for with .updates(), the ones the server refreshed itself, and requests nobody handled.

Live

The queries SvelteKit is holding in its client cache for the current page, each with its arguments and the last value the panel saw for it.

  • Batched queries are listed per argument.
  • Each entry says which call last set its value: the server render, or the command or form that refreshed it.

Endpoints

Every query, query.batch, query.live, command, form and prerender in the project, found by walking src the way SvelteKit does.

  • The URL and HTTP contract of each one, and its input and output types from TypeScript.
  • JSON Schema from Zod, Valibot or any Standard Schema validator.
  • A playground that calls the real endpoint and gives you the matching curl.
  • Forms get real inputs built from their schema, and the server's validation issues show up next to the field they belong to.
  • Warnings for remote files nothing imports, and for duplicate names or signatures.

Explorer

The endpoint list as a page of its own at /__remote-devtools/ on your dev server: every remote function laid out like an API reference, with a file tree beside it.

  • Find a function by the module that declares it, or by the pages and components that import it.
  • Pick a folder, a file or a single function to narrow the list.
  • The list follows your edits: save a remote file and it updates.

Set it up

  1. Install it as a dev dependency.

    bun add -D sveltekit-remote-devtools

    pnpm, npm and yarn work too.

  2. Add the plugin after sveltekit().

    // vite.config.ts
import { sveltekit } from '@sveltejs/kit/vite';
import { defineConfig } from 'vite';
import { remoteDevtools } from 'sveltekit-remote-devtools';

export default defineConfig({
	plugins: [sveltekit(), remoteDevtools()]
});

  3. Run vite dev and click the remote button in the bottom-right corner, or press Alt+Shift+R. The explorer is at /__remote-devtools/.

Audit with an agent

The dev server also serves the endpoint list and the recorded calls as JSON. A skill for coding agents reads both and proposes fixes for:

  • Functions that duplicate each other, or nearly do.
  • Functions and remote files nothing imports.
  • Inputs taken with 'unchecked' instead of a schema.
  • A query called once per row that should be a query.batch.
  • Refreshes the client asks for with .updates() that the server never handles.

Install the skill for your agent:

bunx skills add mastermakrela/sveltekit-remote-devtools

Or paste this prompt. The skill ships inside the package, so nothing else to install:

Read node_modules/sveltekit-remote-devtools/skills/remote-functions-audit/SKILL.md and follow it to audit this app's remote functions.

Good to know

Works with
SvelteKit 2.27 and later (including 3), Vite 6.3 and later, Svelte 5.25 and later, any package manager.
Production
Adds nothing to your build. The plugin only runs during vite dev.
Types
Input and output types need TypeScript 5 or 6 in your app. Without it, everything else still works.
Vite DevTools
If you use Vite DevTools, the panel moves into its dock instead of floating.

How it works, the options and the caveats are in the README. The app in the videos is examples/counting-sheep.
